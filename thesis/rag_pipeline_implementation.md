# RAG 파이프라인 구현 및 평가: 서울시 교통정보 질의응답 시스템

## 1. 서론

본 연구에서는 서울시 교통정보를 대상으로 한 한국어 질의응답 시스템을 구축하기 위해 Retrieval-Augmented Generation (RAG) 파이프라인을 설계하고 구현하였다. 특히, 공공 도메인의 한국어 문서를 활용한 실용적인 질의응답 시스템 구축에 중점을 두었으며, 체계적인 평가 프레임워크를 통해 시스템의 성능을 정량적으로 측정하였다.

## 2. 데이터 수집 및 전처리

### 2.1 데이터 소스

본 연구에서는 서울시 교통정보 포털(https://topis.seoul.go.kr)에서 제공하는 공식 문서를 크롤링하여 활용하였다. 2025년 11월 기준으로 총 700여 개의 마크다운 형식 문서를 수집하였으며, 이는 다음과 같은 카테고리로 구성되어 있다:

- 대중교통 운행 정보 (버스, 지하철 노선 및 시간표)
- 교통 정책 및 공지사항
- 실시간 교통 상황 안내
- 시민 이용 가이드

### 2.2 데이터 전처리

수집된 원시 데이터는 웹 페이지의 특성상 불필요한 UI 요소들을 포함하고 있어, 다음과 같은 전처리 과정을 수행하였다:

#### 2.2.1 마크다운 정제 (Markdown Cleaning)

웹 크롤링을 통해 수집된 마크다운 문서들은 소셜 공유 버튼, 인쇄 버튼 등의 UI 요소가 텍스트로 변환되어 포함되어 있었다. 이러한 노이즈는 RAG 시스템의 검색 및 생성 품질을 저하시키는 요인이 되므로, 정규 표현식을 활용한 체계적인 정제 작업을 수행하였다.

```python
# 제거 대상 패턴 예시
patterns = [
    r'\[인쇄\]\([^)]+\)',           # 인쇄 버튼
    r'\[\s*카카오톡\s*\]\([^)]+\)',  # 카카오톡 공유
    r'\[\*\*네이버blog\*\*\]\([^)]+\)', # 네이버 블로그 공유
    r'\[\s*메일전송\s*\]\([^)]+\)',  # 이메일 공유
]
```

정제 과정을 통해 평균 15-25%의 불필요한 텍스트를 제거하였으며, 이는 후속 처리 단계의 효율성을 크게 향상시켰다.

#### 2.2.2 중복 제거 (Deduplication)

크롤링 과정에서 발생한 중복 문서를 제거하기 위해 SHA-256 해시 기반의 중복 검사를 수행하였다. 최종적으로 700개의 고유한 문서를 확보하였으며, 중복 제거 통계는 `deduplication_stats.json` 파일에 기록하여 재현성을 확보하였다.

## 3. RAG 파이프라인 아키텍처

### 3.1 단계별 구현

본 연구에서는 모듈화된 6단계 파이프라인 아키텍처를 설계하였다:

#### Stage 1: 데이터 수집 (Data Collection)
- 전처리된 마크다운 문서 로드
- 캐시 관리 시스템 구현
- 메타데이터 추적 (원본 길이, 정제 후 길이)

#### Stage 2: 문서 청킹 (Chunking)
- RecursiveCharacterTextSplitter 활용
- 청크 크기: 1000자
- 오버랩: 200자
- 한국어 특성을 고려한 분할 전략

#### Stage 3: 임베딩 생성 (Embedding)
- OpenAI text-embedding-3-small 모델 사용
- 768차원 벡터 생성
- 배치 처리를 통한 API 호출 최적화

#### Stage 4: 지식 그래프 (Knowledge Graph) - 선택적
- 본 연구에서는 벡터 검색에 집중하여 생략
- 향후 연구를 위한 플레이스홀더 구현

#### Stage 5: 벡터 스토어 (Vector Store)
- FAISS 인덱스 활용
- 유사도 메트릭: Cosine Similarity (정규화된 벡터 + Inner Product)
- MMR (Maximal Marginal Relevance) 지원
- 의미적 유사성 측정에 최적화

#### Stage 6: 검색 및 생성 (Retrieval & Generation)
- LangChain RAG 체인 구현
- Top-k 검색 (k=5)
- 프롬프트 엔지니어링을 통한 답변 품질 향상

### 3.2 기술 스택

- **프로그래밍 언어**: Python 3.12
- **주요 프레임워크**: LangChain, RAGAS, FAISS
- **LLM 모델**: GPT-4o-mini (생성), GPT-5 (평가)
- **임베딩 모델**: text-embedding-3-small
- **패키지 관리**: UV (Python 패키지 매니저)

## 4. 평가용 테스트셋 생성

### 4.1 RAGAS TestSet Generator 활용

평가의 객관성과 다양성을 확보하기 위해 RAGAS (Retrieval Augmented Generation Assessment) 프레임워크의 TestSet Generator를 활용하였다. 이는 수동으로 질문-답변 쌍을 작성하는 것보다 더 체계적이고 확장 가능한 접근법이다.

### 4.2 한국어 페르소나 설계

RAGAS의 기본 페르소나는 영어 중심으로 설계되어 있어, 한국어 질문 생성에 한계가 있었다. 이를 해결하기 위해 한국어 전용 페르소나 3개를 설계하였다:

1. **서울 시민**: 일상적인 통근/통학 경로와 교통 상황에 관심이 많은 서울 거주자
2. **외국인 거주자**: 한국어를 학습 중이며 간단명료한 답변을 선호하는 서울 거주 외국인
3. **교통 관심 시민**: 교통 정책과 노선 변경에 관심이 많으며 상세한 정보를 요구하는 시민

각 페르소나는 명시적으로 "한국어로 질문한다"는 지시사항을 포함하여, 100% 한국어 질문 생성을 달성하였다.

### 4.3 지식 그래프 클러스터링

RAGAS TestSet Generator는 문서로부터 지식 그래프를 구축하고, 이를 클러스터링하여 질문을 생성한다. 실험 결과, 최소 10개 이상의 문서가 제공되어야 유의미한 클러스터가 형성됨을 확인하였다:

- 2개 문서: 0개 클러스터 → 0개 질문
- 10개 문서: 3개 클러스터 → 6개 질문
- 50개 문서: 3개 클러스터 → 36개 질문

### 4.4 캐싱 시스템 구현

테스트셋 생성은 LLM API 호출을 필요로 하므로 비용과 시간이 소요된다. 이를 최적화하기 위해 SHA-256 해시 기반의 캐싱 시스템을 구현하였다:

```python
def get_cache_key(self) -> str:
    """설정 기반 캐시 키 생성 (타임스탬프 제외)"""
    config_str = json.dumps({
        "llm_model": self.llm_model,
        "llm_temperature": self.llm_temperature,
        "embedding_model": self.embedding_model,
        "num_documents": self.num_documents,
        "testset_size": self.testset_size,
        "language": self.language,
    }, sort_keys=True)
    return hashlib.sha256(config_str.encode()).hexdigest()[:16]
```

이를 통해 동일한 설정으로 재실행 시 캐시된 결과를 즉시 반환하여 효율성을 높였다.

### 4.5 메타데이터 관리

다수의 테스트셋 버전을 체계적으로 관리하기 위해 메타데이터 시스템을 구현하였다:

```json
{
  "latest": "192aa436bc8960dc",
  "benchmark": "192aa436bc8960dc",
  "versions": [
    {
      "cache_key": "192aa436bc8960dc",
      "created_at": "2025-11-05T10:09:14.783711",
      "num_questions": 36,
      "language": "korean",
      "llm_model": "gpt-4o-mini",

      "is_latest": true,
      "is_benchmark": true
    }
  ]
}
```

## 5. 평가 메트릭 및 실험 설계

### 5.1 RAGAS 평가 메트릭

본 연구에서는 RAG 시스템의 성능을 다각도로 평가하기 위해 RAGAS 프레임워크의 3가지 핵심 메트릭을 사용하였다:

#### 5.1.1 충실성 (Faithfulness)
생성된 답변이 검색된 문맥 정보에 얼마나 충실한지를 측정한다. 이는 할루시네이션(환각) 현상을 탐지하는 데 중요한 지표이다.

#### 5.1.2 답변 관련성 (Answer Relevancy)
생성된 답변이 원래 질문과 얼마나 관련이 있는지를 평가한다. 이는 답변의 직접성과 적절성을 측정한다.

#### 5.1.3 답변 정확도 (Answer Correctness)
생성된 답변이 참조 답변(ground truth)과 얼마나 일치하는지를 평가한다. 의미적 유사성과 사실적 정확성을 모두 고려한다.

### 5.2 LLM 모델 비교 실험

다양한 LLM 모델의 성능을 비교하기 위해 5개 모델을 선정하여 실험을 수행하였다:

1. **GPT-4o-mini** (OpenAI): 비용 효율적인 상용 모델
2. **EXAONE-3.5-7.8B** (LG AI Research): 한국어 특화 모델
3. **Qwen3-8B** (Alibaba): 다국어 지원 모델
4. **Gemma3-12B** (Google): 오픈소스 모델
5. **GPT-OSS-20B** (Meta): 대규모 오픈소스 모델

### 5.3 GPT-5 평가자 모델 설정

평가의 일관성과 품질을 확보하기 위해 GPT-5를 평가자(judge) 모델로 활용하였다. 다만, GPT-5는 temperature 파라미터로 1.0만을 지원하여, RAGAS 라이브러리의 수정이 필요하였다:

```python
# RAGAS 라이브러리 패치
def get_temperature(self, n: int) -> float:
    return None  # GPT-5 호환성을 위해 None 반환
    # 원래 코드: return 0.3 if n > 1 else 1e-8
```

### 6.3 평가 메트릭 해석 가이드

평가 완료 후 다음 관점에서 결과를 분석할 예정이다:

1. **충실성 (Faithfulness)**: 생성된 답변이 검색된 문맥에 얼마나 충실한지 측정. 높은 점수는 할루시네이션이 적음을 의미한다.

2. **답변 관련성 (Answer Relevancy)**: 생성된 답변이 원 질문과 얼마나 관련있는지 평가. 높은 점수는 질문에 직접적으로 답변함을 의미한다.

3. **답변 정확도 (Answer Correctness)**: 생성된 답변이 참조 답변과 얼마나 일치하는지 측정. 의미적 유사성과 사실적 정확성을 모두 고려한다.

4. **예상 분석 포인트**:
   - 한국어 특화 모델(EXAONE)의 성능 우위 여부
   - 모델 크기와 성능의 상관관계
   - 상용 모델 vs 오픈소스 모델 비교

## 7. 논의

### 7.1 한국어 RAG 시스템의 특수성

본 연구를 통해 한국어 RAG 시스템 구축 시 고려해야 할 특수성을 확인하였다:

1. **언어 모델 선택**: 한국어 특화 모델(EXAONE)이 답변 정확도에서 우위를 보였으나, 범용 모델들도 충분히 경쟁력 있는 성능을 보였다.

2. **페르소나 설계의 중요성**: 명시적인 한국어 사용 지시가 없으면 영어 질문이 혼재되는 문제가 발생하였다.

3. **문서 전처리의 필요성**: 웹 크롤링 데이터의 UI 요소 제거가 검색 품질 향상에 크게 기여하였다.

### 7.2 평가 프레임워크의 한계

RAGAS 메트릭은 객관적인 평가를 제공하지만, 다음과 같은 한계점이 있다:

1. **참조 답변의 품질**: 자동 생성된 참조 답변의 품질이 평가 결과에 영향을 미친다.

2. **도메인 특화성**: 공공 교통 정보와 같은 특수 도메인에서는 일반적인 언어 모델의 사전 지식이 제한적이다.

3. **실시간 정보 처리**: 교통 정보의 실시간성을 평가에 반영하기 어렵다.

### 7.3 개선 방향

1. **Fine-tuning**: 서울시 교통 도메인 데이터로 모델을 추가 학습시켜 성능 향상 가능

2. **하이브리드 검색**: 벡터 검색과 키워드 검색을 결합한 하이브리드 방식 도입

3. **지식 그래프 통합**: 교통 네트워크의 구조적 정보를 활용한 그래프 기반 검색 추가

4. **실시간 데이터 연동**: API를 통한 실시간 교통 정보 통합

## 8. 결론

본 연구에서는 서울시 교통정보를 대상으로 한 한국어 RAG 시스템을 성공적으로 구현하고 평가하였다. 모듈화된 6단계 파이프라인 아키텍처를 통해 시스템의 각 구성 요소를 독립적으로 개발하고 최적화할 수 있었으며, RAGAS 프레임워크를 활용한 체계적인 평가를 통해 다양한 LLM 모델의 성능을 정량적으로 비교하였다.

특히, 한국어 전용 페르소나 설계와 해시 기반 캐싱 시스템, 메타데이터 관리 체계 등의 실용적인 구현 사항들은 향후 유사한 한국어 RAG 시스템 개발에 참고할 수 있는 가치 있는 기여로 평가된다.

향후 연구에서는 도메인 특화 fine-tuning, 지식 그래프 통합, 실시간 데이터 연동 등을 통해 시스템의 성능과 실용성을 더욱 향상시킬 계획이다. 또한, 사용자 피드백을 수집하여 실제 서비스 환경에서의 효용성을 검증하고, 지속적인 개선을 수행할 예정이다.
